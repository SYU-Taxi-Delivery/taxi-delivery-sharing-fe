# 내 참여 · 모집 (#10)

로그인 사용자용 `/my`에서 내가 참여한 모집과 내가 만든 모집을 전환한다. 모집 상태와
내 참여 상태를 따로 표시하고, 참여 취소는 #9의 상태·시간 정책을 따른다. 작성자 관리는
기존 `/posts/{id}` 상세의 수정·마감·모집 취소로 연결한다. 전체 탭·탭별 전체 건수는 계약이
없어 추가하지 않았다.

API 명세가 미정인 1차 화면 구현이다. 운영 화면에는 가짜 이력이나 API를 넣지 않으며,
로그인 연동 전에는 로그인 상태 확인 안내를, 인증 연결 후 이력 API 연결 전에는
이력 연동 준비 안내를 표시한다.

## 연결 방법

`myHistoryApi.ts`의 `myHistoryOperations`를 확정된 adapter로 교체한다. 기존 `apiFetch`를
사용하되 URI·인증 전송 방식·서버 DTO·오류 코드는 #18 계약을 따른다. 아래는 화면용
operation과 모델이며 서버 계약이 아니다.

- `list(tab)`: 현재 로그인 사용자의 해당 이력만 반환한다. `tab`은 `participated` 또는
  `created`이며 응답은 `{ content, serverTime }`다. 일반 카드는 `PostSummary` 필드와
  현재 관계 `AUTHOR`·`JOINED`·`CANCELLED`를 제공한다. 인원은 작성자를 포함한다.
- 동일 모집에 반복 참여·취소한 경우 같은 논리 관계의 최신 상태 한 건을 반환한다.
  이벤트 로그를 여러 카드로 보내지 않는다. 작성 이력의 소유자와 참여 이력의 사용자는
  서버가 세션에서 판정하며 클라이언트 사용자 id를 권한 근거로 삼지 않는다.
  중복 id·탭과 다른 관계·잘못된 필드는 추측해서 보정하지 않고 조회 오류로 처리한다.
- `REMOVED`는 `{ id, status: "REMOVED", relation }` 최소 이력만 제공한다. 화면에는
  "관리자에 의해 삭제된 모집"만 표시하고 제목·장소·참가자·링크·상세 진입을 제공하지 않는다.
- `serverTime`과 `referenceTime`은 timezone이 포함된 시각이다. 참여 취소는 현재 `JOINED`·
  OPEN/FULL/CLOSED이며 T-10분 전까지만 제공한다. 정확히 T-10부터 차단하고 최종 판정은
  서버가 한다. `FINISHED`·`CANCELLED`·`REMOVED`는 기록으로 표시한다.
- `leave(id)`: 서버가 내 참여 취소를 확인한 경우에만 resolve한다. 성공 후 이력을 다시
  조회해 관계·인원·상태를 갱신한다. 응답 유실은 실패로 단정하거나 자동 재전송하지 않고
  최신 상태를 확인한다. FULL은 자리가 나면 OPEN이 될 수 있고 직접 마감한 CLOSED는 유지된다.
- 보호 API의 `ApiError(401)`은 기존 `handleUnauthorized()`로 로그인 만료를 처리한다.
  인증 provider 아래의 상태는 사용자 변경·로그아웃·만료 시 초기화한다.

페이지가 이력과 서버 시계를 소유하고 선택한 취소 대상에만 `useParticipation`을 연결한다.
각 카드에 자동 재조회 구독을 만들지 않는다. 확인된 취소 직후 관계만 갱신하고 인원·모집
상태는 후속 조회로 확인한다. 성공 후 조회 실패는 별도로 안내하고 변경을 재전송하지 않는다.
이력의 정렬·페이지 방식은 서버 계약 확정 후 adapter에서 연결한다.

## 개발 미리보기

`pnpm dev` 실행 후 `/my-preview`를 연다. 운영 환경에서는 404다. 모의 계정과 이력은
개발 경로에서만 제공하며 새로고침·상황 변경 시 초기화된다. 두 탭에 택시·배달과
OPEN/FULL/CLOSED/FINISHED/CANCELLED/REMOVED를, 참여 탭에는 참여 취소 관계도 제공한다.

상단 "상황"에서 빈 이력·조회 실패·참여 취소 실패·취소 성공 후 조회 1회 실패·T-10분
경계를 확인할 수 있다. 경계 상황의 첫 카드는 진입 약 5초 후 참여 취소가 마감된다.
미리보기는 실제 시계를 기준으로 하며 날짜가 바뀌어도 미래/과거 이력을 유지한다.

## 검증

관련 테스트와 확인 명령은 다음과 같다. 실제 실행 결과는 작업 보고에서 구분한다.

```sh
pnpm exec vitest run src/features/my src/app/my-preview
pnpm format:check
pnpm lint
pnpm typecheck
pnpm test
pnpm build
```

모의 응답 테스트는 실제 서버의 본인 이력 격리·동일 관계 제약·세션 권한·시간 판정의
증거가 아니다. 해당 항목은 #18 계약과 실제 연동 후 별도로 검증한다.

2026-10-20 로컬 Chromium에서 작성/참여 전환·취소 성공 후 카드 갱신·확인창의 초기
포커스/Tab/Escape/복귀를 확인했다. 320/375/768/1024/1440px에서 가로 넘침이 없고
Figma 아이콘이 원래 크기로 로드됨을 확인했다. 실제 기기·스크린리더는 확인하지 않았다.
