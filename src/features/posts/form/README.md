# 모집글 작성·수정 (#8)

> 연동 상태(2026-10-27): `POST /api/posts`·`PATCH /api/posts/{id}`에 연결했다(`postFormApi.ts`). 유사 모집 API가 없어 `findSimilar`는 빈 결과를 반환한다. 설정·불일치·요청 목록은
> [docs/backend-integration.md](../../../../docs/backend-integration.md)를 참고한다.

API 명세가 미정인 상태의 1차 구현이다. 로그인 사용자용 `/posts/new`(배달은
`?type=DELIVERY`)와 작성자용 `/posts/[id]/edit` 화면, 입력 검증, 유사 모집 제안,
서버 거절 안내, 수정 잠금을 구현했다. 운영 화면에는 가짜 모집·API를 추가하지
않으므로 연동(#18) 전에는 요청 시 "연동을 준비하고 있어요"를 표시한다.

개발 서버의 `/post-form-preview` 상단 "상황" 선택에서 작성(유사 없음·유사 있음·
유사 조회 실패·같은 시각 중복·응답 유실)과 수정(참여자 없음·다른 참여자 있음·마감·
취소·저장 중 참여 발생)을 모의 응답으로 확인한다. 운영 환경에서도 공개 데모로 열린다.

## 연결 방법

`postFormApi.ts`의 `postFormOperations`를 확정된 adapter로 교체한다. 기존 `apiFetch`를
사용하고 URI를 추측해 넣지 않는다.

- `findSimilar(request)`: 서버 유사 모집 조회. `PostSummary` 형태의 배열을 반환하며
  OPEN만 표시한다. 같은 날짜·유형, 정규화 완전일치, ±30분 판정은 서버가 한다.
- `create(request)`: 생성된 모집 id를 반환한다. 성공 후 `/posts/{id}`(#7)로 이동한다.
- `load(id)`: `EditablePost`(상태, 작성자 여부, 작성자 외 JOINED 수, 현재 인원, 초안)를
  반환한다. 기준시각은 `toSeoulParts`로 날짜·시간 초안으로 바꾼다.
- `update(id, request)`: 잠긴 수정에서는 장소·기준시각·정원이 빠진 요청을 받는다.
- 서버 거절은 `PostFormError(kind, fieldErrors)`로 바꿔 던진다. `invalid`(fieldErrors를
  해당 칸에 표시), `duplicate`(같은 작성자·같은 분), `time`(서버 시각 기준 10분 조건),
  `conflict`(수정 중 상태·참여 변경, 최신 정보 재조회), `forbidden`, `notFound`.
  401은 `ApiError`를 그대로 던지면 로그인 만료 안내로 바뀐다. 그 밖의 오류는 응답
  유실로 보고 자동 재전송 없이 결과 확인을 안내한다.
- `PostRequest`의 `referenceTime`(+09:00, 분 단위)은 adapter에서 택시
  `departureTime`/배달 `orderDeadline`으로 바꾼다. 음식 종류 값은 보내지 않는다.

## 입력 정책

- 제목 60, 전할 말(설명) 1,000, 장소·음식점 각 100, 주문 안내 500, 링크 500자.
  자유 텍스트는 NFC 후 양끝 공백만 제거해 코드포인트로 센다(Q-LENGTH). 글자 수는 칸
  옆에 표시하고, 칸을 벗어나거나 제출하면 오류를 보여 준다.
- 외부 소통 링크는 선택이며 `https://`만 허용한다.
- 정원은 작성자 포함 택시 2~4명, 배달 2~10명이며 범위 끝에서 버튼이 비활성이다.
- 날짜는 서비스 디자인에 맞춘 자체 달력(`DatePicker`)으로 고른다. 오늘 이전 날짜는
  선택할 수 없고, 방향키·Home/End·PageUp/PageDown으로 이동하고 Enter로 고르며 Escape나
  바깥 누르기로 닫힌다. 닫히면 날짜 칸으로 포커스가 돌아온다.
- 시간은 같은 디자인의 `TimePicker`로 시(00~23)와 분(5분 단위)을 고른다. 선택한 날짜 기준으로
  지금부터 10분을 넘게 남지 않은 시각은 비활성으로 보여 준다. 방향키·Home/End로 이동하고
  Enter로 고르며 ←/→로 시·분 열을 오간다. 5분 단위는 화면 정책이며 API는 분 단위를 받는다.
  수정에서 그대로 둔 기존 시각은 5분 단위가 아니어도 막지 않는다.
- 날짜·시간은 Asia/Seoul 분 단위이며 지금부터 10분을 넘게 남아야 한다(정확히 10분은
  거절). 최종 판정은 서버 timestamp다. 수정에서 바꾸지 않은 기준시각은 다시 막지 않는다.
- 택시·배달 초안은 화면 메모리에 각각 보관하고 활성 유형만 전송한다(Q-DRAFT).
- 작성 중 취소·목록 이동은 폐기 확인창을 띄우고, 돌아가기는 입력과 포커스를 되돌린다.
- 유사 모집은 등록 전에 한 번 확인하며 작성을 막지 않는다. 값을 바꾸면 결과를 지운다.
  조회 실패 시 "다시 확인"과 "확인 없이 등록"을 제공한다.

## 수정 잠금

`editAccess`가 판정한다. 작성자가 아니거나 CANCELLED·FINISHED·REMOVED면 수정 폼을
열지 않는다. 작성자 외 JOINED가 있거나(FULL 포함) CLOSED면 장소·기준시각·정원을
잠그고 제목·전할 말·링크·주문 안내만 보낸다. 유형은 항상 바꿀 수 없다. CLOSED 제한은
기능정의서 p.44 기준이며 p.16 일반 규칙과의 차이는 API 계약 때 확인한다.

[택시 작성](https://www.figma.com/design/3fvNUDoN2M1PP9A3rYDxsB/?node-id=42-1430),
[배달 작성](https://www.figma.com/design/3fvNUDoN2M1PP9A3rYDxsB/?node-id=2-4661)의
목록 복귀·제목·카테고리·장소·날짜/시간·정원 스테퍼·전할 말·취소/등록 구성을 따랐다.

- 배달 "음식 종류" 선택은 PRD 필드가 아니어서 넣지 않았다(Q-FIELDS, AC-UI-FORM-05).
- 배달 "수령 장소·모임 장소·수령 날짜/시간"은 PRD의 음식점명·수령 장소·주문 마감
  날짜/시간으로 바꾸고 선택 주문 안내를 추가했다.
- 시안에 없는 외부 소통 링크(선택)를 추가했다(COORD-004).
- 날짜·시간 칸은 시안처럼 각각 전체 너비로 세로 배치했다. 나란히 두면 한쪽 오류
  문구 때문에 다른 칸이 밀렸다.
- 장소 칸의 위치 아이콘·지도 선택은 계약이 없어 텍스트 입력만 제공한다.
- 수정 진입은 상세(#7)의 작성자 관리 카드에 있는 "모집글 수정"이다.
