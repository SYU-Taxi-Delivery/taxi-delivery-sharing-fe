# 로그인·회원가입·인증 상태 (#5)

> 연동 상태(2026-10-27): 로그인·로그아웃·세션 확인을 연결했다(`authApi.ts`). 현재 사용자 API가 없어 로그인 응답을 브라우저에 기억하고 인증 요청으로 세션을 확인한다. 회원가입은 백엔드와 도메인(`@syu.ac.kr`)·항목(학번)이 달라 미연결이다. 설정·불일치·요청 목록은
> [docs/backend-integration.md](../../../docs/backend-integration.md)를 참고한다.

API·인증 명세가 미정인 상태의 1차 구현이다. 학교 이메일(`@syuin.ac.kr`) 로그인과
회원가입(이메일 인증번호 포함) 화면, 인증 상태, 보호 화면 안내, 역할별 메뉴, 로그아웃을
구현했다. 비밀번호 재설정 요청·새 비밀번호 입력 화면(#29)도 제공하며 실제 재설정 API는
미연결이다. 운영 화면에는 가짜 사용자·API를 추가하지 않는다. 로그인은 실제 API를
사용하고 회원가입·비밀번호 재설정은 요청 시 연동 준비 안내를 표시한다.
학교 도메인은 `auth.ts`의 `SCHOOL_EMAIL_DOMAIN` 한 곳에서 정한다.

첫 화면(`/`)은 같은 로그인 화면을 제공한다. 로그인 성공 또는 이미 인증된 상태에서는
`/posts`로 이동한다. `/login?next=...`의 보호 화면 복귀 동작은 유지한다.

개발 서버의 `/auth-preview`에서 모의 계정(`student@syuin.ac.kr`, `admin@syuin.ac.kr`,
미인증 `unverified@syuin.ac.kr`, 비밀번호 `preview-password`)으로 로그인·권한·세션
만료·로그아웃 실패를 확인할 수 있다. `/signup-preview`에서는 인증번호 `123456`으로
가입 흐름을, 비밀번호 `compromised-password`로 서버의 차단 목록 거절을 확인한다.
두 화면 모두 새로고침하면 초기화되며 운영 환경에서는 404다.

## 연결 방법

`authApi.ts`의 `authOperations`를 확정된 계약에 맞는 adapter로 교체한다. 기존
`apiFetch`를 사용하고 쿠키 세션이면 `credentials: "include"`를 전달한다. URI를
추측해 넣지 않는다.

- `me(): Promise<unknown>`: 현재 사용자 조회. 세션이 없으면 `null`을 반환하거나
  `ApiError(401)`을 그대로 던진다. 응답은 `toCurrentUser`가 id/displayName/role만
  남기며 형식이 다르면 로그인으로 취급하지 않는다.
- `login({ email, password })`: 세션이 발급된 경우에만 resolve한다. 실패는
  `ApiError`를 그대로 던지면 상태 코드별 안내(400·401 동일, 403 새로고침·이메일 인증
  상태 확인, 429 제한)를 표시한다. 403의 원인을 이메일 미인증으로 단정하지 않는다.
  성공 후 provider가 `me()`로 다시 확인한 뒤 진입한다.
- `logout()`: 204와 이미 만료된 세션(401)을 모두 정상 종료로 본다.

회원가입은 `signupOperations`를 교체한다. 화면은 Figma 순서대로 이메일 인증을 먼저
마친 뒤 가입을 요청하므로, 인증 결과를 가입 요청에 묶는 방식(세션·일회용 토큰 등)은
adapter와 #18 계약이 정한다.

- `requestCode(email)`: 6자리 인증번호 발송. 가입 여부와 관계없이 같은 결과(202)여야 한다.
- `verifyCode(email, code)`: 성공 시에만 resolve. 400은 불일치·만료, 429는 실패 초과.
- `register({ email, displayName, password })`: role 등 다른 필드를 보내지 않는다.
  401·403은 인증 만료로 보고 인증을 다시 시작한다.

루트 레이아웃의 `AuthProvider`가 앱 전체에 상태를 제공한다. 화면에서는
`useAuth()`로 `status`(`checking`·`authenticated`·`anonymous`·`expired`·`unavailable`)와
`user`를 읽는다. 보호 화면은 `<RequireAuth>`, 관리자 화면은 `<RequireAuth role="ADMIN">`로
감싼다. 다른 기능의 API가 401을 받으면 `handleUnauthorized()`를 호출하고, 403이면
`<AccessDenied />`를 표시한다. 이 가드는 화면 안내일 뿐이며 실제 권한 판정은 서버가 한다.

사용자가 바뀌거나 로그아웃·만료되면 provider 아래 트리를 다시 마운트하므로 이전
사용자의 화면 상태(명단·초안 등)가 남지 않는다. 화면 복귀(focus·visibilitychange)와
뒤로 가기 캐시 복원(pageshow)에서 `me()`를 다시 확인한다. 일시적인 재확인 실패는
로그인 상태를 유지하며, 보호 API의 401이 최종 판단이다.

## 성공·실패 처리

- 로그인: 이메일은 양끝 공백만 제거하고 `@syuin.ac.kr` 도메인을 확인한다. 비밀번호는
  trim·정규화하지 않는다. 요청 중에는 중복 제출을 막고, 실패하면 비밀번호만 비운 뒤
  비밀번호 칸으로 포커스를 옮긴다. 서버 오류 원문은 표시하지 않는다.
- 회원가입: 이메일 인증 후 이메일을 고정하고, 바꾸려면 "다른 이메일로 변경"으로 인증을
  다시 시작한다. 재발송은 60초 간격(서버 429가 최종 판단), 인증번호는 숫자 6자리만 받는다.
  닉네임은 NFC 후 양끝 공백만 제거해 2~20 코드포인트, 비밀번호는 NFC 후 15~128
  코드포인트이며 trim하지 않는다. 차단 목록 검사는 서버가 한다. 필드 오류는 해당 칸을
  고치면 사라진다.
- 로그인 후 이동: `?next=`는 같은 출처의 `/` 경로만 허용하고 `//`, `\`, 제어 문자,
  `/login` 반복은 `/`로 바꾼다. 보호 화면의 로그인 링크는 현재 검색 조건도 유지한다.
- 로그아웃 서버 실패(네트워크·500): 이 기기의 사용자 정보는 지우고 실패를 안내하며
  "서버 로그아웃 다시 시도"를 제공한다. 이 동안 `me()`가 성공해도 자동으로 다시
  로그인하지 않는다(AC-AUTH-002-07).

## 비밀번호 재설정 (#29)

- `/forgot-password`: 학교 이메일로 재설정 링크를 요청한다. 요청 완료 안내는 가입 여부와
  관계없이 동일하며 이메일이 존재하는지 표시하지 않는다.
- `/reset-password?token=...`: 새 비밀번호·확인을 입력하고 변경 완료 후 로그인으로
  돌아간다. 자동 로그인하지 않는다. 15~128 코드포인트·NFC·공백 유지 정책은 회원가입의
  검증 함수를 재사용한다.
- 토큰이 없거나 중복된 query이면 입력 폼 대신 새 링크 요청을 안내한다. 실제 유효성은
  서버가 판정해야 하며, 만료·사용된 링크는 동일한 사용 불가 안내로 처리한다. 토큰이
  바뀌면 이전 입력·진행 상태를 초기화한다. 토큰·비밀번호를 저장소나 로그에 남기지 않는다.
- 두 경로는 검색 색인을 막고 새 비밀번호 경로에는 `no-referrer` 메타데이터를 적용한다.
- `passwordReset.ts`의 `PasswordResetOperations`는 화면 콜백이며 서버 API 계약이 아니다.
  `requestLink(email)`·`resetPassword({ token, password })`는 실제 성공에만 resolve해야 한다.
  기본 구현은 `notConnected` 오류를 반환해 실제 발송·변경을 완료했다고 표시하지 않는다.
- UI 오류는 `PasswordResetError`의 `invalidLink`·`passwordRejected`·`rateLimited`로 구분한다.
  HTTP 상태·URI·메일 발송·토큰 수명·세션 무효화는 백엔드 계약 확정 후 adapter에서 연결한다.

개발 서버의 `/password-reset-preview`에서 링크 요청,
`/password-reset-preview?mode=reset`에서 새 비밀번호 입력을 확인한다. 상단의 "상황"으로
성공·요청 제한·네트워크 오류·만료/사용된 링크·비밀번호 거절·토큰 없음을 재현한다.
실제 메일 발송·비밀번호 변경은 없으며 운영 환경에서는 두 미리보기 주소 모두 404다.
