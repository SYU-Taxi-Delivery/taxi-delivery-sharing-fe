# 공개 댓글 (#11)

모집 상세의 참여 안내 아래에서 로그인 사용자가 댓글을 조회·등록하고 본인 댓글을
삭제한다. 기존 상세 레이아웃과 확인창을 재사용한다. 실제 API는 연결하지 않았으며,
운영 화면은 가짜 댓글 대신 연동 준비 안내를 표시한다.

## 화면 규칙

- 참여 여부와 무관하게 OPEN/FULL/CLOSED에서 기준시각 T 전까지 작성한다. 참여 신청의
  T-10분 마감과 다르다. 상세의 서버 시계와 상태를 재사용하고 제출 직전에도 확인한다.
- FINISHED/CANCELLED에서는 기존 댓글 조회·본인 삭제만 제공한다. 입력 중 종료되면
  작성한 내용을 읽기 전용으로 유지하고 등록을 막는다. REMOVED는 댓글도 표시하지 않는다.
- 내용은 NFC 정규화·양끝 공백 제거 후 1~500 코드포인트다. 내부 공백·줄바꿈을 유지하고
  글자 수와 입력 오류를 안내한다. HTML은 일반 텍스트로 표시한다.
- 삭제는 본인 댓글에만 제공하고 확인창을 거친다. 모집 작성자 권한으로 다른 댓글을
  삭제하지 않는다. 관리자 타인 댓글 삭제는 Issue #11의 선택 확장으로 남겼다.
- 서버가 확인한 성공 전에는 댓글을 추가하거나 제거하지 않는다. 등록 성공 후 목록
  재조회가 실패하면 등록 완료와 조회 실패를 구분하며 같은 POST를 다시 보내지 않는다.
- 등록 실패에는 입력을 보존한다. 처리 여부를 모르는 오류는 추가 변경을 막고
  "최신 댓글 확인"을 제공한다. 재조회 후 사용자가 결과를 확인하고 재시도하며,
  본문 일치만으로 중복 여부를 판정하거나 자동 POST를 재전송하지 않는다.
- 401은 기존 로그인 만료 처리를 사용한다. 조회 403은 이전 댓글을 지우고 권한 안내를,
  모집 없음은 상세 재확인을 요청한다. 모집·사용자·operation 변경 후 늦은 응답은 무시한다.

## 추후 API 연결

`comments.ts`의 `CommentsOperations`는 화면 콜백이며 URI·서버 DTO 계약이 아니다.

- `list(postId)`: `{ content: [...] }`. 표시용 항목은 `id`, `authorName`, `content`,
  `createdAt`, `isMine`만 사용한다. adapter가 `createdAt ASC / id ASC` 순서를 제공하며
  화면은 불투명 ID를 추측해서 재정렬하지 않는다. 삭제 행은 전달하지 않으며
  `isDeleted: true`가 있어도 본문을 화면에 전달하지 않는다.
- `create(postId, content)`·`remove(postId, commentId)`: 서버가 변경 성공을 확인한 경우에만
  resolve한다. 인증 사용자의 소유권·상태·입력·soft delete는 서버가 최종 판정해야 한다.
- `CommentsError("invalid"|"forbidden"|"closed")`는 저장되지 않았음이 확인된 거절에 사용한다.
  응답 유실·잘못된 변경 성공 응답 등 처리 여부를 모르면 `unknownOutcome` 또는 일반 오류로
  전달한다. HTTP 상태·문제 코드·페이지 계약·삭제 결과의 세부 매핑은 #18에서 확정한다.

## 개발 미리보기와 검증

개발 서버의 `/comments-preview`에서 실제 `CommentsPanel`을 확인한다. 상단 "상황"으로
모집 중·정원/직접 마감·빈 댓글·조회 실패·등록 거절·저장 후 응답 유실·삭제 거절·5초 후
종료·완료/취소·로그인 만료·권한 없음·삭제 모집을 재현한다. 실제 서버에 저장하지 않으며
운영 환경에서도 공개 데모로 열린다.

```sh
pnpm exec vitest run src/features/comments src/features/posts/detail src/app/comments-preview
pnpm typecheck
pnpm lint
pnpm format:check
pnpm test --maxWorkers=1 --no-file-parallelism
pnpm build
```

관련 TC는 `AC-COORD-001~003`, `AC-UI-A11Y-03`이다. 모의 응답 통과는 실제 서버 인가,
저장 정합성·정렬·세션·응답 유실 처리의 통합 검증을 대신하지 않는다.

2026-10-30 검증: 전체 Vitest 35파일·774건(댓글 모델·패널·상세 통합·미리보기 신규 68건),
타입·린트·포맷·운영 빌드가 통과했다. 로컬 브라우저에서 등록 후 목록 갱신, 삭제 확인창의
Tab/Escape와 포커스 복귀, 확인 후 삭제, 응답 유실 시 변경 차단·재조회로 저장 1건 확인,
T 경계의 읽기 전용 초안 보존, 취소 모집의 조회/본인 삭제, 권한 없음·삭제 모집의
내용 비노출을 확인했다. 320/768/1024/1440px에서 가로 넘침이 없었고 운영 서버의
`/comments-preview`는 404이며 모의 내용이 없었다. 실제 API·실기기·스크린리더는 미검증이다.
