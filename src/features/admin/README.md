# 관리자 기본 화면 (#12)

`/admin`에서 ADMIN이 신고 목록·상세를 확인하고 신고를 해결/반려하거나 모집을 별도로
숨긴다. 실제 API는 연결하지 않았으며 운영 기본 동작은 연동 준비 안내다.

## 접근과 표시

- 기존 계정 메뉴의 관리자 진입점을 사용하고 `RequireAuth role="ADMIN"`으로 감싼다.
  비로그인·STUDENT에는 신고 조회나 변경 콜백을 호출하지 않는다. ADMIN을 스스로
  부여하는 UI는 없다. 실제 API도 서버의 세션·권한 검사를 반드시 수행해야 한다.
- PENDING 신고를 먼저 표시하며 같은 상태 내부 순서·페이지 계약은 adapter가 정한다.
  목록·상세의 로딩, 빈 목록, 없는 신고, 실패와 재시도를 구분한다.
- 신고 사유·선택 상세, 신고자 식별 ID, 대상 모집의 제목·본문·상태·기준시각과 처리 결과만
  투영한다. 이메일·학번·전화·참가자 명단·외부 링크 필드는 사용하지 않는다.
- REMOVED 대상은 원래 제목·본문·기준시각을 제거하고 삭제 안내로 표시한다.

## 조치

- 해결/반려는 PENDING에만 제공한다. 응답의 신고 ID·모집 ID·요청한 상태와 서버의
  처리 시각·처리자를 검증한 후 목록·상세를 갱신한다. 신고 해결은 모집 숨김과 별개다.
- 모집 숨김은 확인창을 거쳐 soft delete 결과를 반영한다. 서버가 확인한 REMOVED와
  삭제 시각·처리자, 활성 참여 취소 또는 완료 이력 유지 결과를 표시한다. 물리 삭제는 없다.
- 처리 중에는 중복 조치를 막는다. 실패를 완료로 표시하지 않고, 응답 유실·잘못된 성공
  응답·충돌은 최신 목록과 상세를 재확인하기 전 추가 조치를 막는다. 자동 재전송하지 않는다.
- 현재 요청의 401은 로그인 만료, 403은 관리자 정보 제거·권한 안내로 처리한다.
  다른 사용자·operation·신고 선택 뒤 도착한 이전 응답은 적용하지 않는다.
- 확인창 닫기와 처리 완료 시 키보드 포커스를 복귀한다. 원래 버튼이 비활성화됐거나
  사라지면 상세 제목으로 이동한다.

## API 연결 경계

`AdminOperations`의 `list`, `load`, `process`, `removePost`는 화면 콜백이며 URI·서버 DTO
계약이 아니다. 기본 구현은 `notConnected`를 반환한다.

- `process`는 서버 처리 결과를 포함한 새 상세를 반환한다.
- `removePost`는 `RemovalResult`를 반환한다. 서버의 `CANCELLED_ACTIVE` 또는
  `PRESERVED_HISTORY`를 표시하며 클라이언트 시계로 삭제 효과를 추정하지 않는다.
- `invalid`는 변경되지 않았음이 확인된 거절에만 사용한다. 변경 응답 자체가 잘못됐거나
  처리 여부가 불명확하면 `unknownOutcome`으로 처리하고 재조회한다.
- 실제 서버 인가·신고/모집 상태 경합·soft delete·참여 일괄 변경·감사 기록·일반 조회의
  콘텐츠 차단은 백엔드와 실제 API 통합 검증에서 확인해야 한다.

## 개발 미리보기

`pnpm dev` 후 `/admin-preview`에서 신고 조회·처리·모집 숨김을 모의 실행한다.
"상황"으로 빈 목록·조회/조치 실패·충돌·응답 유실·잘못된 성공 응답·권한·만료를 재현한다.
조치 후 "확인 화면"에서 같은 모의 상태를 사용하는 일반 목록·상세·작성/참여 이력을
확인한다. "상세 대상"에서 진행 중/완료 모집을 선택해 이력 보존 차이를 확인한다.
실제 데이터는 변경하지 않으며 운영 빌드에서도 모의 관리자 데모를 확인할 수 있다.

관리자 댓글 관리·계정 권한 편집·일괄 조치·관리 통계는 기본 구현에 포함하지 않는다.
테스트와 API 대기 범위는 [프론트 테스트 안내](../../../docs/frontend-testing.md)를 따른다.

2026-10-30 검증: 전체 40파일·860건(신규 관리자/공통 준비 84건), 타입·린트·운영 빌드가
통과했다. 로컬 Chromium에서 해결/숨김 분리, 서버 처리자·시각 표시, 진행 중 참여 취소와
완료 이력 유지 안내, 응답 유실/잘못된 성공 응답의 재조회, STUDENT·비로그인·401/403 차단,
확인창 Tab/Escape·포커스 복귀를 확인했다. 같은 모의 상태로 일반 목록 제외·상세 차단·
작성/참여 이력 tombstone을 확인했고, 목록·상세 모두 320/768/1024/1440px에서 넘침이 없었다.
운영 서버의 `/admin`은 로그인 안내를, `/admin-preview`는 404를 표시했다.
실제 API·DB·실기기·스크린리더는 검증하지 않았다.
