상태 변형은 enum만 바꾸지 않고 아래 규칙으로 관계·인원·시각까지 함께 초기화한다.

- FULL은 작성자 1명과 `capacity-1`명의 서로 다른 JOINED 관계를 생성한다. 행에서 지정한 B를 포함하고 부족한 인원은 독립 J1~J9 테스트 사용자로 채운다. N/C를 임의로 JOINED로 만들지 않는다. OPEN의 명시된 인원도 `1+JOINED`와 일치시킨다.
- 단일 조회에 여러 모집을 넣으면, 같은 작성자라고 명시한 경우를 제외하고 서로 다른 학교 인증 학생 W1~Wn을 작성자로 둔다. 같은 작성자의 유효 모집은 같은 Seoul 날짜/분에 겹치지 않게 시각을 나눈다. 이 규칙은 목록/페이지/추천/성능 시드에도 적용한다. 중복 거절 테스트의 신규 입력은 아직 저장된 모집이 아니다.
- CLOSED는 명시된 인원과 JOINED 관계를 유지한다. 모집 CANCELLED는 기존 B 등 활성 참여를 CANCELLED로 전환한 이력을 생성하고 JOINED를 남기지 않는다. 따라서 CANCELLED 모집의 B는 취소 이전 참가자이며 현재 관계는 CANCELLED이다.
- 각 조회/변경 실행에는 현재시각을 하나만 사용한다. FINISHED도 현재시각을 바꾸지 않고 과거 기준시각을 준비한다. 행에 명시한 T/현재시각이 우선이며, FINISHED의 T만 생략되면 현재시각을 분 단위로 내린 값보다 1분 이전 T를 사용한다(기본 now17:30→T17:29). 혼합 목록은 진행 모집 T18:00·완료 모집 T17:00으로 구분한다. 최종 JOINED/취소 이력은 보존하며, 정확히 T를 검증하는 Q-TIME은 명시 경계를 그대로 사용한다.
- REMOVED는 진행 중 삭제 시 이전 JOINED를 CANCELLED로 만든 시드와 FINISHED 이후 삭제 시 관계를 보존한 시드를 구분한다. 같은 행이 두 경우를 다루면 각각 독립 실행한다.

각 TC 전 DB/모의 응답/시계/인증 상태를 초기화한다. 흐름 테스트는 별도 시드를 생성해 단계 사이 결과를 이어간다. 실제 계정·운영 API·실명은 fixture에 넣지 않는다. 변경 API의 정상/권한/도메인 검증은 유효 Origin/CSRF를 기본 시드로 준비하고, CSRF 전용 케이스에서만 이를 변형한다. 모집/참여/신고/댓글 ID는 테스트환경에서 생성한 식별자이며 특정 URI·DTO 계약을 가정하지 않는다.

한 행은 한 행동에 대한 검증이다. 같은 행동의 여러 입력은 독립 변형으로 실행하고 `TC ID/유형/입력/시각/관계/수준`을 실행 ID에 붙인다. 예를 들어 `AC-INPUT-PLACE-03/TAXI/departure/101/FE`와 `.../BE-U`는 별도 실행이다. 성공과 실패가 서로 다른 행동 결과이면 별도 행으로 기록한다. 명시하지 않은 공통 모집 행동은 TAXI와 DELIVERY 각각 실행한다. 특정 유형 전용 행은 해당 유형에만 실행한다.

`FE+BE-U`, `FE+BE-I`처럼 수준이 병기된 행은 독립된 검증 두 개를 요구한다. FE는 화면·요청·응답 대응만, BE는 권한·저장·정합성을 검증한다. FE 모의 응답으로 DB의 변화나 원자성·서버 권한을 통과시킬 수 없다. 권장안 행은 아래 잠정 계약의 입력·기대값으로 실행을 준비한다. 조건부 인증의 외부 연동 자료가 없으면 실행 기록에서 BLOCKED로 남기며, 확장 보류 행은 필수 완료 게이트에 포함하지 않는다.

| ---- | ------------------------------------------------------------- | ------------------------------------------------------------------ | -------- |
| FE   | 기존 Vitest·React Testing Library·jsdom, fetch 모의·고정 시계 | 테스트 파일/테스트명/TC ID·실행 로그, 화면과 사용자 조작 assertion | FE       |

담당은 책임 역할이며 팀원의 이름 배정은 별도 진행한다. 모든 서비스 케이스는 아직 미실행이다. `권장안 우선 분류·미구현/미실행`은 잠정 기준 적용, `조건부 권장안·미구현/미실행`은 채택 인증 한 개에만 적용, `권장안 확장 보류/미실행`은 기본 범위에서 제외다. 기존 PRD가 명확한 행은 `미구현/미실행`을 유지한다. 실제 성공 여부는 별도 실행 기록에만 남긴다. BE-U 행의 HTTP 상태/응답 값은 잠정 API 매핑 참고이며 서비스의 도메인 결과/오류만 검증한다. 실제 HTTP 응답·DB 보존의 통과 증거는 BE-I/FLOW가 필요하다.

### 미관측 화면의 권장 배치

상세 하단에는 시간순 댓글과 작성/본인삭제/ADMIN 단건삭제, 상세의 신고 진입에는 5가지 PRD 사유와 선택 상세내용 폼을 둔다. 수정은 기존 작성폼과 상태별 잠금을 재사용하며 추천은 작성폼 입력 아래에서 조회 실패/재시도와 작성 계속을 제공한다. ADMIN은 신고 목록→상세→해결/반려와 별도 게시글 삭제 행동을 제공한다. 각 위치에 로딩·빈 상태·오류/재시도·접근성 안내를 정의한다. 이는 Q-MISSING-DESIGN 권장 배치이며 Figma에서 확인한 화면 목록을 늘리지 않는다.

## 실행 기록과 완료 판정

아직 서비스 TC의 실행 기록은 없다. 기존 `src/lib/api.test.ts`·`src/app/page.test.tsx`는 보일러플레이트 검증이며 본 문서 케이스를 통과한 증거로 계산하지 않는다. 구현 후 각 행에 실제 테스트 파일/테스트명/자동화 여부를 연결한다.
