# 백엔드 협조 요청 목록 — 모집글·접근 제어·마이페이지

기준일: 2026-10-31 (Asia/Seoul). FE 기준: main `fb6c1f9fbf69a5937f482926a354d4679d6177de`.
담당 범위에서 지금 가능한 FE 테스트·수정 결과는 [검증 보고서](weekly-fe-verification-2026-10-31.md)에 기록했다.
아래는 전달용 정리이며 실제 메시지 전송·담당자 합의·백엔드 변경은 수행하지 않았다.

## 먼저 맞출 통합 조건

- 로그인 가능한 작성자 A·참여자 B·제삼자 C 테스트 계정과 테스트 서버를 준비한다. 운영 계정이나 비밀번호를 이 문서에 기록하지 않는다.
- FE의 학교 이메일은 `@syuin.ac.kr`, 기존 연동 문서에 기록된 BE 가입 정책은 `@syu.ac.kr`이다. 실제 학교 도메인·학번/이름/닉네임 정책을 확정해 테스트 계정과 일치시킨다.
- demo의 Basic 인증 계정과 로컬 비밀번호 로그인 계정을 구분한다. FE의 `POST /api/auth/local/login`으로 로그인 가능한 LOCAL_CREDENTIAL이 필요하다.
- 테스트 환경의 `BACKEND_ORIGIN`, FE 자신의 origin인 `NEXT_PUBLIC_API_BASE_URL`, 프록시를 통과한 세션·CSRF 쿠키를 확인한다. 기존 같은 origin 프록시를 사용한다.

## 공통 오류 회귀 확인

[BE PR #16](https://github.com/SYU-Taxi-Delivery/taxi-delivery-sharing/pull/16)은 이번 확인 시 open·미병합이다.
지원하지 않는 Accept에서 변경이 저장된 후 406을 반환하던 문제의 수정이다.
FE 기본 요청은 `Accept: application/json`을 사용한다. PR이 반영된 테스트 서버에서 정상 JSON과 401/403/404/409, 잘못된 Accept의 오류 본문·저장 여부를 각각 확인한다.
이 문서는 PR 병합이나 배포를 요청/실행한 기록이 아니다.
